# 多层 Special Block：完整结果总表

更新时间：2026-09-10

## 阅读说明

所有内部结果均来自 **Amazon x1**（602,453 vectors，768D）、containment 查询、K=10、1000 queries、100 CPU threads。延迟均为 1000-query batch 的 warm median；每点运行 7 repeats，丢弃 cold repeat 0。`Recall min` 表示该点所有 repeats 中的最低 Recall。

本文分开四种口径：

- **六档共享配置**：每个层数使用一套跨 0.5%--75% workload 共享的结构阈值，是主要部署口径。
- **高选择率共享配置**：只在 80%--100% workload 内重新选择一套共享阈值，不能解释为六档配置的无调参外推。
- **固定 T1 消融**：单层和双层都固定 `T1=1k`，只改变 T2，用于隔离第二层增量效果。该表使用 warm mean，因为对应 compact evidence 的预声明主统计是 warm mean。
- **逐 workload oracle**：每个 workload 可更换结构，仅表示已测离散网格中的能力上界，不是一套可直接部署的统一配置。

`vs 0` 大于 1 表示比 plain 快；`2 vs 1` 大于 1 表示双层比单层快。不同表之间若参数、Recall 门槛或统计量不同，不应直接横向排序。

## 4. 逐 workload oracle：六档离散能力上界

| 选择率 | 0层 ms | 最佳1层：参数 / L / ms / vs 0 | 最佳2层：参数 / L / ms / vs 0 | 2 vs 1 |

| 0.499% | 39.201 | T1=32k / 1375 / 40.658 / 0.964x | 32k/200k / 1375 / 40.268 / 0.973x | 1.010x |

| 9.907% | 656.284 | T1=32k / 7000 / 790.144 / 0.831x | 32k/100k / 6875 / 776.964 / 0.845x | 1.017x |
| 24.915% | 1533.380 | T1=128k / 8000 / 1447.450 / 1.059x | 64k/64001 / 8125 / 1713.795 / 0.895x | 0.845x |
| 49.971% | 5072.390 | T1=32k / 550 / 295.583 / 17.161x | 16k/200k / 450 / 310.929 / 16.314x | 0.951x |
| 74.994% | 41353.500 | T1=32k / 1150 / 574.830 / 71.940x | 16k/200k / 625 / 490.104 / 84.377x | 1.173x |

这个表说明：两层相对单层的明确系统收益首先出现在 75% 档；25% 和 50% 上最佳单层优于最佳双层。

高选择率 oracle 与共享配置基本相同，仅有两处变化：85% 的最佳双层从 `16k/400k,L=125,320.900 ms` 变为 `16k/500k,L=100,313.653 ms`；100% 的最佳单层从 `T1=128k,L=125,438.012 ms` 变为 `T1=256k,L=100,402.089 ms`。这两个结构轴仍触及已测边界，故只作为 oracle 提示，不更新共享部署结论。

## 9. 总结

| 环境 | 当前证据支持的选择 | 证据强度 |
|---|---|---|
| 低于约 1% | plain；第二层相对同 T1 单层仅基本持平 | 正式重复实验，但无显著性检验 |
| 约 10% | plain 仍最快；若必须使用 T1=1k overlay，双层明显优于单层 | 正式固定 T1 消融 |
| 约 25% | 依赖查询结构；标准 workload 单层近似 plain，历史 28.61% workload 调优单层优于 plain | 两套查询分布方向不一致，不能只看选择率 |
| 约 50% | Special Block 大幅优于 plain，但单层略优于双层 | 正式共享与 oracle 一致 |
| 约 75% | 双层优于单层，且两者均大幅优于 plain | 正式共享与 oracle 一致 |
| 80%--96.7% | 高选择率专用共享配置下双层逐点优于单层 | 五个离散 filtered 点；非连续区间定理 |
| 100% | 双层优于单层 | 独立空 predicate control，不外推 97%--99% |

最严谨的总括是：**两层的价值不是普遍降低固定开销，而是在过滤条件足够宽、查询能够授权更大 block 时进一步压低达到同等 Recall 所需的搜索预算。选择率是重要变量，但不足以单独决定最佳层数；查询标签结构、T1/T2 和独立调优同样关键。**

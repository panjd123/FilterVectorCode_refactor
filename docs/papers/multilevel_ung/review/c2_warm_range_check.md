# C2 两次 warm 观测范围定向数值审计

**结论：所核查的数值和范围推导一致；未发现配对分析或 CI 被冒充的情况。** 本报告只评价指定审计数据和脚本，不给论文总体评分。没有修改论文或原脚本，没有重跑 benchmark，也没有写入任何远程仓库。

## 输入与复核范围

- 本地输入为 `warm_repeat_points.csv`、`warm_repeat_comparisons.csv`、`manifest.json`，脚本 `/tmp/mlung-c1-repeat-audit.py`，以及冻结 `factorial_equal_recall.csv`。
- 本地独立计算全部 **95 个 crossing、190 个 warm Recall 值、35 个 comparison**；另外通过授权 SSH 只读核查全部 **95 份原始 search_time_details.csv**，并核对两份 all_points.csv 和冻结 factorial 的 SHA256。不是只相信 manifest 中的通过标记。
- 两份输出 CSV、原脚本和本地冻结 CSV 的 hash 与 manifest 全部一致；95 份原始 timing 文件与 points/manifest 的路径及 hash 全部一致。
- 95 个 crossing 的键集合与冻结表 `status=complete` 完全相同，没有重复、漏行或 NC 混入。31 个 NC 被排除；comparison 数量是 **8 个 T/L + 9 个 TLT/L + 9 个 TLT/TL + 9 个 TLT/TLL = 35**，不是 36。缺少的正是 T/L 的 `sel_30`。

## 公式和逐行结果

每个已选 Lsearch 的原始 timing 都恰有 Repeat 0、1、2，丢弃 Repeat 0。原始 all_points 的 batch size 全部为 **B=1000**。两次 warm 的时间、Recall 与 points CSV 逐值一致：

- `QPS = 1000 × B / median(t1,t2)`。两次观测的 median time 等于其算术均值；这不是两次 QPS 的算术平均。95 行重算值与冻结 QPS 完全相同（本次浮点相对差为 0）。
- `recall_min = min(r1,r2)`。95 行与冻结 recall_min 一致，190 个 warm Recall 均在 [0.90,1]。本审计核对的是冻结所选预算，不重新证明其相对所有执行预算的最小性。
- `warm_cv = sample_stdev(t1,t2) / mean(t1,t2)`，标准差分母为 n−1；95 行与输出及原 all_points 一致。CV 中位数 0.00870677，最大值 0.27032245。这是两点样本的描述量，不是标准误或 CI。
- 对 A/B，独立枚举 `(1000B/tAi)/(1000B/tBj)` 的四个组合。这里两者 B 相同，因此等于 `tBj/tAi`。35 行的最小值、最大值和 median-time QPS ratio 全部一致（复核容差 1e-12）。
- `observed_ranges_overlap` 恰等价于 `lower ≤ 1 ≤ upper`，即两组各两次 QPS 所形成的 min/max 区间是否重叠。这不是统计意义上的等价性检验。

## 应弱化的结果及建议表述

- **TLT/TL，60% 与 80%：**分别为 `[0.9494,1.0328]`、`[0.9603,1.0357]`，均跨 1。建议“当前两次 warm 观测接近持平，无法据此判定稳定优劣”，不能把 0.9905×/0.9977× 写成稳定退化。
- **TLT/TLL，30% 与 80%：**分别为 `[0.9588,1.0854]`、`[0.9854,1.0114]`，均跨 1。原先“8/9 档点估计更快”作为点估计计数仍成立，但其中 30% 不能被描写为明确收益，80% 不能描写为明确损失。
- **TLT/TL，95%：**范围 `[1.0723,1.0981]`，四组合均大于 1。可写“这两次观测中，加 L2 对应 7.2%–9.8% 的 QPS 提高”，不能写统计显著或跨运行稳定。
- **TLT/TLL，95%：**点估计 1.2510×，范围却为 `[1.0037,1.5024]`。原始 TLL 时间是 1792.18/2639.23 ms，TLT 是 1785.50/1756.66 ms；TLL 的样本 CV 约 27.0%。可报告点估计和宽范围，但“L2 Trie 稳定提高 25.1%”不受支持。该比较也不能与上一条 TLT/TL 的更窄范围混用。
- **其他约 1%–2% 点差：**TLT/TL 的 99%，以及 TLT/TLL 的 10%、60%、99%，虽四组合范围未跨 1，仍只支持“本次两次 warm 观测中更快”。尤其 TLT/TL 99% 的下界仅 1.0011，不应升级为可靠的一般规律。
- 两种重点比较在其他档的非重叠范围同样不证明统计显著；更大点差可以如实报告，但仍受两次同查询批次重复、固定主机状态与开发集选择影响。

## 脚本与统计口径判断

脚本第 85–91 行的 extrema 公式与四个笛卡尔积比率完全等价；不存在误将 Repeat 1 对 Repeat 1、Repeat 2 对 Repeat 2 当作配对样本的问题。manifest 明确声明 `not_a_confidence_interval=true`，并说明 repeats 不按 paired 处理，区间分离也不代表统计显著或复现稳定。因此当前审计文件的措辞是准确的。

**必须保留的限制：**四个比率由两次 A 和两次 B 观测组合而来，不是四次独立实验；范围没有置信水平，也不能作为误差条暗示 95% CI。它只描述已记录的两次 warm，既不改变冻结 crossing 选择，也不改变 TLT 来自开发集观察的事实。

一个非阻断的复用边界：points CSV 未单列 `num_queries`，但脚本从原 summary 读取 B；本次所有 B 均为1000，推导无误。若未来扩展到不同 batch size，独立消费者应读取原 summary 的 B 或显式保存它，不应永久硬编码1000。

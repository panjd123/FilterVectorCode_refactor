# C1 固定配置复核（冻结 Amazon 开发集）

**TLT 是在九个 workload 上保持不变的 `2L[T|LT]`：Trie base、L1=LNG、L2=Trie。它来自开发集观察，不是 held-out 或预先注册配置。** 本次只复算现有 CSV，没有新增实验。

- **TLT/Plain：**九档等权几何均值 **24.5886×**；最差 **0.4817×**（sel_30，即 QPS 比 Plain 低 51.83%）；7/9 档 QPS 更高。
- **TLT/TL：**九档等权几何均值 **1.0810×**；最差 **0.9188×**（sel_30，即 QPS 比 TL 低 8.12%）；5/9 档 QPS 更高。60% 与 80% 比率接近 1，不能仅凭两次 warm 的点估计声称稳定收益。
- **覆盖状态：**L、TL、TLT 均 9/9 crossing；T 为 8/9，30% 档原始 status 为 `unavailable`，max_recall=0.8882。NC 不补零，也不作为已达标 QPS 纳入平均。
- **与事后全网格赢家的距离：**TLT/oracle 几何均值 0.8683，最差 0.4817（sel_30）。这只用于完整网格分析，不能冒充 query-time selector。
- **核验：**逐 workload 重新计算的 TLT/Plain 与 CSV `speedup_vs_L` 全部一致（相对容差 1e-12）；均值使用 exp(mean(log(ratio)))，各 workload 等权。未合并父线程另行重建的 cross-repeat 范围，也未生成 CI。

**建议主文表述：**“固定 TLT 配置在 Amazon 九个开发集查询批次均达到目标 Recall；它相对 Plain 在 7/9 档提高吞吐，同时保留中间档位的退化。添加 L2 相对固定 TL 的收益并不单调。”不要把每档赢家的吞吐拼成 TLT 的结果。

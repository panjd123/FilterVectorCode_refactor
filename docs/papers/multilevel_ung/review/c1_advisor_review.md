## 2. 同一个例子是否讲清 prefix、block、retag 与覆盖

### 结论：逻辑成立，主线已可复述；与 PDF 的衔接还不够直接

第 15–25 行的三组例子可以顺序讲清四件事：

1. `{b}` 是 LNG 的唯一最小入口，能通过包含边到 `{b,c}` 和 `{a,b}`。
2. Prefix 只保留排序后的前缀连接，所以 `{b}` 只能直接覆盖其前缀分支，`{a,b}` 必须成为额外入口。
3. 三个 group 各含一个向量、阈值 T=1 时，`{b,c}` 自身的质量为 1，不发出 block；累加到 `{b}` 达到 2，发出一个拥有这两个组的 block。`{a,b}` 所在分支仅有一个点，留在基层。
4. 把唯一 LNG 入口转交给 L1 后，L1 没有通往基层 residual `{a,b}` 的路径；即使队列无限，该向量也不可达。完整 prefix frontier 保留 residual 的 L0 入口，因此这个失覆盖不发生。

这四步与 PDF 第 6 页 §5.3、Proposition 4 及第 7 页 Figure 3 一致。第 25 行将穷尽覆盖限定在入口保留、授权 block 独立入口、局部图可达和必要基层路径等条件下，也正确指出 LNG base 可以使用完整 prefix frontier。这里讲的是入口合同与搜索状态的组合性质，不是“Trie 边天生保证 Recall”。

我没有发现该小例子或这一限定版覆盖表述的逻辑冲突。完整前沿中的入口被 retag 后，其所有前缀后代仍位于同层某个已标记 block 下；该 owner 的根标签包含查询，并由独立保留的 portal 覆盖。保留在 L0 的入口则依赖所声明的基层路径条件。证明不需要不同尺度的分区嵌套，也不需要状态跨层跳转。

**现在仍会停下来确认的地方：**

- 第 15 行的 `singleton groups` 应直接说“三个组各含一个向量”。组内只有一个向量与标签集合只有一个标签是不同概念；例子中后两组都有两个标签，英语术语容易造成第一次听报告时的误读。
- 第 23 行说“论文新增三联图”，应明确为 **PDF 第 7 页 Figure 3**。论文第 2 页 §2.2 与第 5 页 Figure 2 仍采用旧四组例子 `{b}`、`{a,b}`、`{a,b,c}`、`{a,c}`。这两个例子各自正确，但导师从 briefing 翻到第一张方法图时会发现成员、block 根和 residual 都变了。口头汇报应固定采用新三组例子，直接指定 Figure 3；没必要为这次定向复审要求全篇统一重写。
- 第 19 行只展示所有向量都合法的正例。若还需解释“整体授权为何保留细层”，可以在同一个例子补一句：Q={b,c} 不能授权根 `{b}` 的 block，但 `{b,c}` 组自身合法，可由基层入口表示。它不需要再引入第四个组。
- 第 25 行的条件适合用一句话讲出核心，再把完整命题留作备查。逐项口述全部条件会把一个很好的小例子变成符号检查。

第 38 行关于 block 数单调不增及 `B(T) ≤ floor(N/(T+1))` 与 PDF 第 4 页、附录 B.1 相符。对整数阈值而言，每个互不重叠的已发出 block 至少有 T+1 个点，故该上界成立。这里没有将 block 大小或授权质量错误地说成单调性质。不过这两个数学性质对 10–15 分钟主线并非必要，可以放在 DRH 被追问时再说明。

## 3. 固定配置替代事后赢家后，能否判断表现

### 结论：可以判断所展示固定结构的开发集表现，仍不能据此判断部署策略或外部竞争力

第 44–60 行已经把比较单位说清楚：四列结构在所有批次中不变，每个批次按同一 Recall 门槛选择已测搜索预算。读者无需从 oracle 结果逆推某个方案，能直接得到以下结论：

- 固定 `2L[T|LT]` 在七档超过 Plain；9.907% 与 30.027% 分别只有 Plain 的 0.612× 和 0.482×。
- 增加第二个 overlay 在前三档的比例为 1.430×、1.147×、1.287×；在 10% 和 30% 有退化，60%/80% 接近持平，95% 为 1.085×，99% 为 1.018×。
- 高平均选择率的巨大恢复在一个 overlay 时就已经出现。第二层在这些批次的大部分增益较小，不能把相对 Plain 的三百多倍都作为“第二层”的贡献。
- 30% 时 Trie base 本身 NC，加入 overlay 后能够达到目标，但仍慢于 Plain。这是有用的结构性边界，固定表现在能够直接保留它。

表格支持“所选固定结构在这些批次上表现如何”，不支持“该结构在看数据之前已被选定”，也不支持“无需按批次选择 Lsearch 的完整在线方案”。第 44 行已声明开发集与统一预算选择口径，因此没有把固定 topology 包装成自动部署策略。

**建议补齐的表格口径：**

- 在第 44 行明确“本表使用 ungated routing；LNG base 配 optimized-LNG entry，Trie base 配 prefix entry”。这是本次 PDF §7.4 和 CSV 的实际设置。当前 briefing 在 profile 段说明了匹配 provider，却没有在固定表附近完整说明；第 7 节随后介绍 DRH gate，容易让人误以为固定多层结果也经过该 gate。

第 60 行重新引入全网格事后赢家没有构成错误，但固定表已经是主证据。在有限时间内不应再花一段逐档讲 oracle，尤其不能把“固定第二层的边际收益”和“各深度重新选择拓扑后的收益”混着说。

## 4. 大 Lsearch 与队列成本解释是否准确

### 结论：准确，且没有把推测写成测量归因

第 81 行给出的 Plain `260,000–400,000`、固定 2L `1,000–5,000` 与 CSV 完全一致。Lsearch 是有界候选容量而非距离计算总量，这个澄清很必要。

PDF 第 6 页 §5.4 的成本表达包含 `(Aq+Pq)Ls`，并明确默认数组队列即使拒绝候选也可能扫描活动容量。因此容量改变可能影响扫描、维护和候选操作成本，不能仅通过邻接扫描或距离计算数量解释全部吞吐差异。

C1 目前用“同时反映导航路径和达到质量门槛所需预算变化”，随后明确“profile 没有单独分离队列耗时”，这符合已有证据。没有将容量比当作加速比，也没有断言队列就是全部瓶颈。该问题已从 C0 的归因缺口转为一条明确的当前限制。

只有一个轻微措辞建议：把“成本会随容量增加”改为“单次操作的扫描或移动成本可能随有效队列长度增长，上界受容量影响”。容量更大并不保证每次操作都更慢，实际 occupancy、候选准入和循环终止都会变化。这不推翻当前解释，只避免将复杂度上界读成实测单调关系。

仍需区分两个覆盖问题：第 23 行是入口 retag 后的结构性不可达，无限容量也不解决；第 81 行是达到测得 Recall 门槛所需容量与运行时间的关系。不能据“Plain 需要大容量”就断言所有 NC 都是队列容量不够。C1 第 113 行专列逐查询可达性诊断，与这个区分一致。

第 79–83 行也正确保持了 profile 与主吞吐的计量边界：阶段均值不能相加替代并发 batch 时间。正反两档 profile 比仅展示一个最大比率更有解释力，应继续留在主汇报。

## 5. DRH/GPU 定位是否合理

### DRH：定位合理，规则细节可以减量

第 99–103 行明确它是无 query 校准的结构规则，当前固定 LNG base，只输出所声明的部分系统配置。Genome/Reviews 接近 Plain、VariousImg 只有 0.205×，以及 v2 仍只有 0.336×都被直接写出；单层人工候选实际上执行 base 的限制也得到正确解释。

`N/T` 作为 block 数的宽松上界与前面的整数点数界相容；同时明确 T 不是局部搜索工作上界，避免把 `T+N/T` 的平方根最小值误讲成延迟最优解。这是本轮必要的理论定位修正。

建议将“后者的 v2 改到 0.336×”补成“另一同 cohort 对照中的 v2 为 Plain 的 0.336×”。PDF 第 10 页说明 v2 是独立 routing cohort，不能用 0.336/0.205 直接计算严格配对的改进倍率。现在两个比率本身正确，这只是避免口头外推。

对短汇报，保留“规则只看 N、R、C”“四个数据集仍都导出两层”“存在明显迁移退化”即可。平方根取整、rho 公式和停止条件可在提问时展开。

### GPU：定位合理，比较对象更清楚

第 105 行先给同一声明层级的 CPU sidecar 与 hybrid 比较：1000.64→90.49 秒、11.06×；再给独立 base 与 hierarchy 阶段中位数之和 141.27 秒相对原 CPU base-only 190.38 秒的 1.35×。这些与本次 PDF 相符，且明确限定为构建后端时间与资源测量。

“输出索引的等 Recall 查询质量尚未验证”“两个 warm”“查询在 CPU 上”均应保留。当前没有把构建速度偷换成同质量完整系统优势。

短汇报可只说 sidecar 的 11.06×与质量缺口；1.35×涉及不同构建任务和独立中位数拼接，需要额外解释。除非导师明确关注全量构建预算，否则这个较难解释的比率放备查更合适。

## 6. 是否适合 10–15 分钟，保留什么

当前是可讲的材料，但逐行讲完仍容易超时。主表、126 格热图、算法性质、两种 DRH gate 和两类构建比率都展开，会挤掉最重要的机制与反例讨论。

建议实际口头顺序如下：

| 时间 | 内容 | 保留的核心材料 |
|---|---|---|
| 0–1 分钟 | AND 过滤、UNG 入口与细组导航两种成本 | 第 7–11 行，N/G 统计 |
| 1–4 分钟 | 同一三组例子的 prefix、block、retag 失覆盖与补全 | PDF Figure 3；直接讲明三个组各一个点、T=1 |
| 4–5 分钟 | 0L/1L/2L 是独立邻接图；授权、入口与层内状态 | 第 29–40 行的简化说明，不推导计数公式 |
| 5–8 分钟 | 固定方案在哪些批次赢、哪里输、第二层有多少边际收益 | 固定配置表，重点读低均值、10%/30%、60%/80%、95%四类现象 |

**主汇报只需三组图表：**新 Figure 3、固定配置表、四行 profile。拓扑记号表可以作为常驻小图例。热图放备查，用于回答交互或赢家问题；不应在固定表之后重新让观众记忆 14 个配置。本次冻结输入允许核查的是 briefing、PDF 和 CSV，没有对 briefing 外链的独立 PNG 做视觉评估，因此不对该热图的字号、配色或实际可读性下判断。

## 7. 汇报前值得落实的少量修改

这些是对当前材料的具体建议，不要求为本轮另起实验：

1. 将 `singleton groups` 改成“每组各一个向量”，明确 Figure 3 的页码/图号；汇报只沿用这一套三组例子。
2. 给固定表补 `ungated`、matched providers、倍率使用未舍入 QPS 三项口径。
3. 让 60%–99% 的容量差异紧随大倍率出现，避免听众先把 300 多倍归因于“多加一层”；强调大部分恢复在一层已出现。
4. 将 block 数证明、完整热图、DRH 公式与组合构建比率移作备查；保留反例和证据边界。
5. DRH-v2 比率加独立 cohort 限定；对接近 1 的倍率继续使用“接近持平”等与重复次数相称的措辞。

C1 的当前研究判断已经更可审查：导师可以确认入口覆盖合同的实质差别，也能看见固定结构在开发集上的收益与退化；仍待证的是这些收益能否跨查询族和数据形态迁移、是否值得额外空间、以及对外部强基线是否具有竞争力。该边界现在表达得足够直接，后续讨论应围绕证据优先级，而不是再把全部注意力花在解释配置名字上。

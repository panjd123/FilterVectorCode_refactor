## 1. 我实际理解到的方法

这是一个支持标签合取过滤的近似向量检索索引：查询要求若干标签同时出现，系统要在满足这些标签的向量中找近邻。难点不是判断单个向量是否符合标签，而是怎样找到足够好的合法搜索起点，以及如何在合法区域内有效导航。

直接出发点是 UNG。它把标签集合完全相同的向量分组，再按集合包含关系的覆盖边连接这些组。这种结构允许从较小的合法标签集合走向较大的合法集合，但寻找最小入口需要消除其他入口已经覆盖的候选；大量细组还会限制向量空间中有价值的跨组移动。

ML-UNG 首先同时改变入口定义和组间连接。标签按固定顺序排列，组只沿 Trie 的最近终止前缀关系连接。查询对每条合法前缀分支保留第一个合法组作为入口。这样不用在不同分支之间做全局的最小超集消除，但必须接受更多入口。`{b}` 与 `{a,b}` 的例子让我理解了这一交换：包含关系能把两者串起来，前缀关系不能，所以后者必须单独进入搜索。实际实现通过标签到组的压缩位图交集及祖先缓存求入口，收益同时涉及结构语义和实现方式。

其次，系统允许把共享前缀的多个细组组合成 block。当查询标签包含于该 block 的根前缀时，block 内所有直接成员都合法，局部向量边便可以跨越原有 exact-group 边界。不同阈值独立构建不同尺度的 block；它们共享向量 ID，但不要求成员分区逐层嵌套，也不一定覆盖全部组。因此这不是通常理解的“从粗层逐步下降到细层”。

查询先授权 block、产生各层入口，再把带物理层标记的状态放入同一个有限队列。状态只读本层邻接；不同层可以各自保留同一向量，也会争夺队列容量。细组入口若被某个合法 overlay 接管，就不再额外保留对应 L0 状态。于是增加 overlay 可能改善局部几何导航，也可能挤掉某些原有入口或搜索状态。覆盖命题只针对完整标签前沿，安全命题只保证在所列不变量成立时不计算不合法向量；两者都不保证有限预算 Recall。

DRH 是用数据规模和度预算生成阈值、层数及层拓扑的结构启发式，当前没有决定 base 类型，也没有解决“哪些查询真的值得使用 overlay”的问题。GPU 工作是支持该额外索引的构建实现，当前构建速度尚未与输出索引的等质量查询结果闭环。

以上是我能从现有材料复述的算法；我尚不能从这些材料证明它相对主要现有过滤检索系统具有普遍优势。

## 3. 会让我停下来追问的具体位置

### 3.1 问题建立得较晚：为什么这两个成本值得优先解决

**位置：第 9–11 行；相关证据到第 46 行和第 66–71 行才出现。类型：材料组织问题，部分信息缺失。**

开头先给 UNG 组织方式和新机制，但没有立即说明这是哪种负载上的严重瓶颈。602,453 个向量形成 482,387 个细组是重要动机，应该和入口/搜索成本一起进入问题页。否则“组很细，所以要 block”仍是一个合理直觉，而不是已建立的主要瓶颈。

我会追问：典型查询会产生多少个入口？细组大小分布、label 长度、prefix 根数和可授权 block 的覆盖质量怎样？Amazon 的高 group/vector 比例是否是收益成立的重要条件？当前材料没有给足这些结构统计，因而不能判断工作面向普遍过滤搜索，还是特定的标签碎片化分布。

### 3.2 入口算法的结构改进与实现改进尚未分离

**位置：第 21 行及第 119 行。类型：论证跳步风险；材料本身已经承认缺少对照。**

Trie provider 用位图交集和祖先缓存，而优化 LNG provider 用候选收集与集合包含判断。`0L[T]/0L[L]` 同时改变了入口语义、数据结构和组间连接，能支持系统比较，不能单独证明某一项贡献占多少。

我会问：如果 LNG 语义也采用相同的 posting 基础设施，最小化仍占多少成本？在相同拓扑上换 provider 时，返回的入口是否都满足该拓扑的覆盖契约？文末的“同 topology 的三 provider 对照”必须先回答这个合法性问题；不是把三个开关放在同一张表里就获得因果归因。

这不否定联合设计贡献，但需要把“联合方案确实更快”和“前缀关系消除了主要计算瓶颈”分开陈述。

### 3.3 block 的直觉清楚，分区构造没有在首次汇报中真正展开

**位置：第 27–29 行。类型：术语负担和信息缺失。**

`canonical Trie`、`uncovered-mass`、`direct members` 在同一段密集出现。第 27 行的两组例子解释了为什么能整体授权，却没有解释为什么某个后代属于本 block、另一个后代被排除，以及哪些组最终留在 base。第 29 行列出构造的性质，却没有让读者看见一次构造。

PDF 第 4 页 Algorithm 2 补上了过程：后序累加，超过阈值发出 block 后将该质量从上级剩余量中移除；成员归属最近的已标记祖先。只读 briefing 不能同样顺畅地恢复这个算法。

我会进一步追问：固定整数标签顺序对 block 的大小、合法查询覆盖率、frontier 大小影响多大？它不改变谓词语义，却能改变此方法的大部分索引结构。当前只说明采用升序，没有给顺序敏感性的判断证据。

### 3.4 多层查询段落精确但不适合在这个位置全部压入

**位置：第 38–42 行。类型：术语负担、材料组织问题，以及真实设计问题。**

第 40 行一次引入状态三元组、排序、层隔离、入口重标记、重复状态、预先标记 seen、block seed 优先、淘汰、最终答案去重及一个九组反例。读者必须在尚未看到正常查询路径之前理解实现级边界条件。

我会停下来要求先画出：同一个查询有哪些合法 block、有哪些残余 base 入口、每个入口在哪一层搜索、结果如何合并。接着再说明预算竞争的反例。PDF 第 5 页两层例子准确展示高层状态可能先被挤掉，但它主要说明失败边界，还不是最省力的正常执行说明。

这里还有不能用改写解决的研究问题：为何用共享队列且优先 block seeds？为何接管后不保留 L0 seed？为什么这些选择比按层分配预算或其他初始化策略更好？当前安全证明允许这些设计，但没有证明其搜索质量；大量 LNG-base overlay 配置低选择率 NC，说明这不只是教学细节。

### 3.5 赢家表不能替代固定方法的贡献表

**位置：第 48–62 行。类型：材料组织问题和信息缺失。**

同一张表左边比较两个 base，右边比较 14 个配置的事后赢家。读者很容易把 6.03× 等 base-only 比率与 21707.89 等多层赢家 QPS 当成同一方案的两种表达。第 60 行及时解释了 oracle，避免了直接误述，但仍没有让导师看到一个固定配置相对于基线的完整曲线，以及仅增加 block 的边际收益。

`0.868` 的 oracle-normalized 几何均值说明接近网格内最优，不等于相对 UNG 的总体提升，也不代表实际工作负载的总吞吐。最差 `0.482` 则意味着某档只有 oracle 的约一半。两者都不应成为跨系统竞争力的替代指标。

第 62 行受控 L2 替换是更干净的证据，但 `8/9` 是方向计数，`1.251×` 是最大值；不能据此推断每档都有稳定收益。尤其 `0.998×` 和其他接近 1 的点只有两个 warm repeats，不应赋予显著性含义。

### 3.6 平均选择率并不是单变量实验

**位置：第 46 行、第 81 行；PDF 第 8 页 §7.3。类型：实验适用范围信息不足，不是数字错误。**

第 46 行正确说明查询批次混入高频 `{1}`，并给了 5% 档的极宽单查询覆盖范围。但表格仍主要以“平均选择率”命名，后面的解释也容易被读成选择率导致性能变化。

PDF 进一步说明 99% 档有 697 个空谓词和 303 个 `{1}`；0.5%、1%、10% 的平均查询标签个数分别为 5.939、5.763、3.396。改变的是谓词组成、标签数和可授权结构等多个因素。99% 的空谓词占比对整体授权尤其关键，briefing 没有交代这个具体组成。

我会要求明确：本文当前证明的是这些冻结查询族上的表现，还是希望声称相同选择率即可预测最优拓扑？后者没有得到这套实验支持。需要按原始 AND 查询、高频 singleton 和空谓词分别看贡献，才能把现象解释得更有因果基础。

### 3.7 极大加速之前，应解释基线为何需要如此大的搜索预算

**位置：第 81 行；PDF 第 6 页式 (5)、第 13 页 Table 9。类型：信息缺失和收益归因问题。**

PDF 给出高平均选择率下 Plain 的 crossing `Lsearch` 达到 260,000、320,000、320,000、400,000。式 (5) 同时明确当前数组队列可能按容量扫描，候选准入和状态扩展均涉及该容量成本。

因此，14–27× 甚至全网格更大的吞吐差异，可能同时来自结构改变、达到 Recall 所需预算改变和队列操作工作量改变。不能仅凭 graph 时间下降就归因为“block 改善几何可达性”。我会问：这套公共执行路径与原始 UNG 查询实现的性能关系如何？把队列成本、距离成本、邻接扫描分开后，主导项是什么？有没有固定 Recall 下队列容量及实际 expansion 数的对照？

这里没有足够证据说基线不公平；使用相同执行路径本身有控制价值。但目前也没有足够证据把巨大倍数推广成相对成熟过滤检索系统的算法优势。

### 3.8 自动方案的正例与反例表述不对称

**位置：第 77–81 行。类型：信息缺失、论证跳步风险。**

Amazon 给出 14.40–26.70×，VariousImg 只写“明确退化”。PDF Table 6 实际是 DRH-v1/Plain = 0.205×，即吞吐约为 Plain 的五分之一；Table 16 的 v2 改善后仍只有同 cohort Plain 的 0.336×。这应当与正例同时给出，否则导师低估路由策略尚未解决的问题。

`T+N/T` 选平方根阈值是可复现规则，但尚不能说明它是一个好的性能代理。R、C 在 briefing 首次出现时也没有说明是局部度与跨边度。四个数据集都导出两层，使“自动深度”尚未得到实际变化场景的验证。

最需要当面确认的是：所有人工候选使用相同 presence gate，以致单层候选始终执行 base。这可以作为相同策略下的结构候选比较，但不能回答“DRH 是否优于认真调好的单层方法”。如果最佳人工方案实际上不执行 overlay，其优势来自拒绝 overlay，而不是该单层索引导航能力。PDF 已坦率说明，briefing 仍需把其对实验问题的影响讲清楚。

### 3.9 GPU 支持性结果缺少质量与存储闭环

**位置：第 83 行、第 121 行。类型：实质证据缺口。**

141.27 秒是独立阶段中位数的和，190.38 秒是原 CPU base，比较对象包含的结构也不同。它支持“加速后 base 加 sidecar 的组合测量量级”，不直接支持一次完整构建实测，也不等于 GPU 相对于相同完整 CPU 索引的纯算法加速。PDF Table 7 的同 sidecar 比较 1000.64→90.49 秒、11.06×更容易解释构建加速，但输出图质量仍未闭环。

此外，构建 RSS/GPU allocation 不能替代最终加载索引的常驻内存、额外边数和 100 个并发查询的 workspace。overlay 引入多份邻接和按层状态；没有这些代价，就不能判断 QPS 的空间换时间是否划算。这一缺口在 briefing 的待办表中没有获得应有位置。

### 3.10 文献表主要在交代写法，没有完成研究定位

**位置：第 85–110 行。类型：材料组织问题，直接比较信息缺失。**

SeRF 行的“先定义……再说明”、ELPIS 行的“应共同报告”、tau-MNG 行的“分开”等，是作者写作或核查准则，不是本方法与该工作的算法差异。16 行出版记录和两个预印本占用了很多首读注意力，却不能让我判断 nearest competing ideas。

汇报中应先回答 UNG、Curator、LSSG 的结构区别，再说明 ACORN/FAVOR 等搜索路线为何是必要实验基线。对范围过滤工作的启发、出版年份及其他写作原则适合备查。当前 PDF §9.2 比 briefing 的文献表更直接，但仍不能据此确认“前缀授权聚合加层局部搜索”在现有工作中具有何种严格的新颖性边界。

“已纳入引用”“已独立审阅”“全文拉取 403”都不构成导师应相信主张的证据。尤其第 116 行的一致性状态只能作为作者报告的状态，本次只读审查不能核验实现与正文一致。

## 5. 哪些证据最有说服力，哪些仍不能据此判断

目前最有说服力的是正反两档 profile 与系统吞吐的并置：

- 0.499%：发现入口由 20.352 降到 0.645 ms/query，seed setup 从 0.195 升到 1.769，Graph 从 2.076 降到 0.868；独立吞吐比较 Trie base 为 LNG base 的 6.03×。
- 9.907%：发现入口仍由 36.631 降到 3.778，但 seed setup 升至 14.744，Graph 升至 323.081；独立吞吐只剩 0.60×。

它们直接支持“入口便宜并不保证总体更快，必须连同后续搜索一起设计”。这比只报最佳倍数更接近本文真正有价值的观察。阶段均值不能相加变成吞吐计时，也不能单独把因果归到某一种图结构。

其次是受控 L2 替换和完整 factorial。它们支持“base、细层、粗层的角色不同”，并反对“全部换 Trie 就更好”的简单结论。但多一层的必要性、额外内存的价值、固定系统对直接竞品的优势，仍没有因此成立。

安全命题提供清楚的实现契约：为什么能免逐邻居过滤。但其中大部分推理是集合包含的传递性与层标记归纳，其研究价值需要来自该组织带来的性能和适用范围，不能把安全命题本身当成充分的强理论贡献。

## 7. 当前应优先解决的研究问题

第一优先级是明确贡献要成立所需的主证据：在同一协议下，一个固定 ML-UNG 配置或预先冻结的策略，相对可靠 UNG 控制和主要直接竞品，是否在有代表性的查询族中提供值得额外索引空间的收益。这同时要求报告加载索引空间、查询工作区、实际搜索预算及失败区。缺少这些，无法给出系统贡献强度的结论。

第二优先级是解释收益来源和适用条件：把高频 singleton/空谓词与原始 AND 查询分开；区分入口实现与入口契约；解释超大 Lsearch 下队列工作；量化 frontier、授权 mass、block 覆盖与标签顺序对结果的影响。这些证据决定论文应声称一般机制优势，还是针对某些结构分布的优化。

第三优先级才是 DRH 的更强自动化、更多深度，以及 GPU 输出质量和联合构建计时。若它们保留为辅助研究，可以明确限制；如果升级为主要贡献，就必须有各自完整的基线和验证。

对本次冻结材料，我能接受的研究结论是：**存在一组可明确描述的入口—连接契约与前缀授权 block 机制；当前 Amazon 实验展示了真实但高度依赖配置及查询组成的成本交换。** 我目前不能接受“已经验证普遍优于现有过滤搜索”“自动选参有效解决部署选择”“构建加速已在同质量索引上闭环”这三种更强判断。需要补的是相应证据，而不只是把已有文字讲得更顺。
